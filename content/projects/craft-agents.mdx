## 背景与问题

Agent 产品在切换模型后端、并行维护多会话、接入 MCP 与本地能力时，容易把 UI、SDK 和运行时状态耦合在一起。这个项目围绕可扩展 Agent 应用架构进行研习与参考实现，重点放在抽象边界、会话隔离和行为验证。

## 使用流程

用户在独立工作区中创建会话，选择后端并接入所需能力。应用把后端流式事件归一化后交给界面消费，同时保持工作目录、偏好和工具上下文的会话级隔离。

## 系统设计

系统以 `AgentBackend` 统一 ClaudeAgent 与 PiAgent 的流式接口，让应用层不直接依赖某个模型供应商。Session 与 Workspace 划分运行生命周期和持久上下文；能力接入层负责将 MCP、API 与 Local Source 转换为可使用的 Agent 工具。

## 关键技术决策

- 用 provider-agnostic 事件流隔离模型 SDK 差异，减少界面随供应商变化而修改的范围。
- 明确 Session / Workspace 的状态边界，避免多任务之间共享错误的目录、偏好或工具上下文。
- 统一外部能力的转换、凭据注入与权限配置流程，降低能力入口分散带来的治理成本。
- 使用结构化 `AgentEvent` 和契约验证表达运行行为，使协议变化能够被追踪。

## 验证方式

通过接口一致性测试与冒烟测试验证不同后端是否遵守同一事件契约，并沿事件全链路定位回归。验证目标是行为一致性和隔离边界，而不是只检查界面是否出现文本。
