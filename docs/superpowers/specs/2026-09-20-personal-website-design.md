# 王楷中个人网站设计方案

日期：2026-09-20  
状态：已完成对话设计确认，等待书面方案复核

## 1. 项目目标

建设一个面向求职与长期技术输出的个人网站。网站首先帮助访问者快速理解王楷中的职业定位，同时通过项目经历、开源证据、博客文章和在线简历证明专业能力。

核心定位：

- 对外身份：AI Agent / AI 应用开发，求职中。
- 求职意向：AI 应用开发实习生。
- 关注方向：Agent 工作流、Tool Calling、MCP、记忆治理、评测与可观测性、AI 应用落地。
- 主要受众：招聘者、面试官、技术同行和开源项目维护者。

成功标准：

1. 新访客能在 5 秒内理解候选人的身份和求职方向。
2. 招聘者能在 30 秒内找到核心项目、最新简历和联系方式。
3. 每项能力主张都有项目内容或公开链接支撑。
4. 作者可以通过 Markdown/MDX 持续发布文章，无需维护数据库。
5. 网站在手机与桌面端均可稳定阅读和导航。

## 2. 参考方向

网站结合两个参考站的优点：

- `jiangxu.net`：清晰的个人品牌首页、项目展示、博客、简历和关于页面。
- `u7u7.top`：可持续扩展的文章分类、标签和内容组织方式。

视觉方向采用“清爽技术作品集 + 少量 Agent 技术感”：主体保持专业、克制和易读；局部使用等宽字体、技术标签和工作流表达，避免将整个网站做成终端界面。

## 3. 技术方案

采用 Next.js App Router、TypeScript 和 MDX。

- Next.js 负责路由、页面生成、元数据和后续交互能力。
- TypeScript 约束项目、文章和简历的数据结构。
- MDX 作为博客正文格式，支持代码块和少量可复用交互组件。
- 首版以静态生成内容为主，不依赖数据库。
- 内容读取层保持独立，未来可在不重写展示页面的前提下接入 CMS。

第一版不建设登录、数据库或文章后台。发布方式为：编辑 MDX、预览、提交到 GitHub、自动构建与部署。

## 4. 信息架构

主导航固定为：

`首页 / 项目 / 博客 / 简历 / 关于`

### 4.1 首页

首页遵循“5 秒建立身份，30 秒证明能力”的信息顺序：

1. 首屏
   - 姓名或常用昵称。
   - 标题：AI Agent / AI 应用开发｜求职中。
   - 说明：关注工作流、工具调用、记忆治理与应用落地。
   - 操作入口：查看项目、查看简历、GitHub。
2. 能力方向
   - Agent 工作流设计。
   - Tool Calling 与外部能力集成。
   - 记忆、会话与工作区治理。
   - Agent 评测、可靠性和安全边界。
3. 精选项目
   - Folio 作为核心项目经历展示。
   - Craft Agents 和 Miniclaw 作为另外两项主要经历。
4. 开源与工程证据
   - 展示公开贡献、PR、测试结果或其他可核验链接。
   - Folio PR #48 是证据之一，不代表全部参与范围。
5. 最近文章
   - 有正式文章时展示最近三篇。
   - 没有正式文章时展示“准备写作的方向”，不生成虚构文章。
6. 简历入口
   - 显示教育与求职方向摘要。
   - 提供在线简历入口；收到最终 PDF 后增加下载。

### 4.2 项目页

项目列表首批包含：

1. Folio：本地优先的 AI 投资研究工作台，重点展示 Agent 研究工作流、工具调用、证据链、技能和评测体系。
2. Craft Agents：重点展示多模型后端抽象、会话隔离、统一能力接入和事件验证。
3. Miniclaw：重点展示身份与工作区建模、结构化记忆、多渠道适配和工程验证。

每个项目有独立详情页，采用以下叙事结构：

`背景与问题 → 用户或使用流程 → 系统设计 → 关键技术决策 → 验证方式 → 结果与证据`

项目页面不把未公开或无法验证的结果写成确定事实。Folio 作为王楷中的项目经历呈现；个人负责范围在后续获得更完整资料后增量补充。

### 4.3 博客页

第一版栏目：

- 求职复盘。
- Agent 工程。
- 学习手记。

文章页支持：

- 标题、摘要、发布日期、分类和标签。
- 草稿和置顶状态。
- 自动阅读时间。
- 代码高亮、目录和标题锚点。
- 上一篇与下一篇导航。

第一版不加入评论、访问量、复杂统计、全文搜索或友链。文章数量增加后再加入搜索、归档和 RSS。

面试复盘支持公开、草稿和隐藏敏感公司信息三类内容策略。

### 4.4 简历页

- `/resume` 始终展示当前最新版。
- 对外标题保持“AI 应用开发实习生”。
- 页面顶部提供邮箱、GitHub 和 PDF 下载入口。
- 历史版本保留在内容目录中，但不生成公开路由。
- 每个版本记录版本标识、更新时间和适用方向。
- 打印样式自动隐藏导航、主题按钮和站点页脚。
- 当前第一版内容来源为 `C:/Users/71865/Desktop/resume/王楷中_简历.md`。

### 4.5 关于页

包含个人简介、墨尔本大学教育经历、技术兴趣、当前状态和联系方式。页面不重复完整简历，而是解释职业方向与持续学习主题。

## 5. 视觉与交互系统

### 5.1 视觉语言

- 浅色作为默认主题：偏白背景、深灰文字、蓝色强调色。
- 支持跟随系统的深色主题，并允许手动切换。
- 中文正文以长文阅读舒适为第一目标。
- 英文技术标签、代码和小型状态信息使用等宽字体。
- 卡片使用细边框、轻圆角和克制阴影。
- 不使用复杂粒子、持续运动背景、装饰性 3D 或过多玻璃效果。

### 5.2 交互规则

- 顶部导航滚动后保持可见。
- 所有可交互元素提供悬停、键盘焦点和触摸状态。
- 项目卡和文章卡整块可点击，同时保留明确文字链接。
- 页面动画仅使用轻微淡入和位移，并遵守减少动态效果的系统设置。
- 移动端使用单栏布局，不压缩正文阅读宽度。
- Folio 首页项目区展示简化工作流：

  `用户问题 → 工具调用 → 证据整理 → 研究结论`

## 6. 内容模型

### 6.1 项目模型

每个项目包含：

- `slug`
- 名称与一句话简介
- 时间或阶段；日期未确认时可以省略，不显示占位文字
- 项目状态
- 个人角色
- 技术栈
- 背景与问题
- 使用流程
- Agent 或系统架构
- 关键技术决策
- 验证方式
- 结果与证据
- GitHub、PR、演示或文章链接
- 首页精选标识

### 6.2 文章模型

每篇文章包含：

- `slug`
- 标题与摘要
- 发布和更新时间
- 分类与标签
- 草稿状态
- 置顶状态
- 可选封面
- 正文

发布时间、阅读时间和文章链接由内容层统一生成，页面组件不自行推断。

### 6.3 简历模型

每个简历版本包含：

- 唯一版本标识
- 更新时间
- 目标岗位
- 是否为当前版本
- Markdown 内容
- 可选 PDF 资源

系统要求只有一个版本被标记为当前版本。历史版本不得生成可索引的公开页面。

## 7. 数据流与维护方式

### 7.1 构建时数据流

1. 内容文件由结构校验器读取。
2. 项目、文章和简历分别转换为统一的类型化数据。
3. 草稿和历史简历在生产构建中被过滤。
4. Next.js 为公开内容生成页面和元数据。
5. 部署平台发布静态资源和必要的应用输出。

### 7.2 内容更新流程

1. 新建或修改 MDX/Markdown 文件。
2. 本地预览内容、布局和链接。
3. 运行内容校验、类型检查和测试。
4. 提交到 GitHub。
5. 自动构建并部署。

GitHub 仅作为项目证据和源码链接。首页不依赖 GitHub API 实时加载内容，避免接口限制或连接失败影响首屏。

## 8. 错误与降级处理

- 项目、文章或当前简历缺少必填字段时，生产构建失败并指出文件与字段。
- 草稿文章不生成公开页面，也不进入站点地图。
- 缺少封面时使用统一的文本型或纯色标识，不显示破图。
- 外部链接不可用时不影响站点主体渲染。
- 找不到内容时显示站内 404 页面，并提供返回项目或博客的入口。
- 第三方脚本不是核心页面的前置依赖。
- 面试复盘中的公司、面试官和内部信息默认需要人工确认后才能公开。

## 9. 测试与验收

### 9.1 自动检查

- 内容模型和必填字段校验。
- 草稿过滤测试。
- 当前简历唯一性测试。
- 项目排序和首页精选逻辑测试。
- TypeScript 类型检查。
- 生产构建检查。
- 核心页面与导航的浏览器流程测试。

### 9.2 人工验收

- 首页、项目、博客、简历和关于页均可访问。
- 手机、平板和桌面无横向溢出。
- 键盘可完成导航、主题切换和链接访问。
- 深浅主题下文字和交互状态保持清晰。
- 项目证据链接与联系方式准确。
- 打印简历不包含站点导航和无关控件。
- 页面标题、描述、图标、站点地图和分享信息完整。
- 性能、无障碍和 SEO 检查以 90 分以上为目标；最终标准是在真实内容下保持稳定、清晰和可访问。

## 11. 第一版不包含的内容

- 登录和账号系统。
- 数据库。
- 在线文章编辑器或管理后台。
- 评论和访问统计。
- 实时 GitHub 数据同步。
- 友链、音乐、图库或个人生活子站。
- 复杂动画和非必要的第三方脚本。
